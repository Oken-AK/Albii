# ADR-0003: 画面遷移・設定・アルバムの保存方式

- ステータス: Accepted
- 日付: 2026-10-13

## 背景

実機確認のフィードバックを受けて、以下の機能を追加する必要が出た。
- 上部のハンバーガーメニューから設定を開く
- 下部タブ（フォト / アルバム / 端末）
- 写真の全画面表示（ビューア）
- グリッド列数のピンチ操作と、その保存
- アプリ内 DB によるアルバム

## 決定

1. **画面遷移**: Navigation Compose は使わない。`MainScreen` の状態（選択タブ、設定の表示有無、ビューアの対象）で切り替える。設定とビューアは全画面オーバーレイとして重ね、戻る操作は `BackHandler` で扱う。理由は画面数が少なく、ビューアに渡すのが一覧のリストと開始位置だけで済むため。
2. **設定の保存**: Jetpack DataStore（Preferences）を使う。並び順、グループ化、列数を保存する。列数は 2〜6 の範囲に丸める。
3. **アルバムの保存**: Room を使う。アルバムと、アルバムに入る写真の URI（`albumId + uri` を主キー）を保存する。写真の実体は複製しない。
4. **列数のピンチ操作**: `detectTransformGestures` で拡大率を見て列数を変える。独自の判定ロジックは書かない。
5. **アイコン**: `material-icons-core` のみ使う。自動ミラー対応の `Icons.AutoMirrored` を使う。

## 結果

- 依存に DataStore、Room（KSP）を追加した。
- 画面遷移ライブラリは入らないため、画面が増えたら本 ADR を見直す。
- アルバムの URI は Photo Picker の権限が再起動後も残るとは限らない。`takePersistableUriPermission` を試みるが、失敗しても握りつぶしている。実機で確認が必要。
- 動画再生（Media3）と情報パネル（Phase 2b）は本 ADR の対象外。
