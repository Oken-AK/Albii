# ADR-0002: サムネイル読込・一覧取得・DI の方針を変更する

**ステータス**: Accepted（ADR-0001 の一部を置き換え）

**日付**: 2026-10-13

**決定者**: GitHub Copilot（AIエージェント）

---

## コンテキスト

ADR-0001 では「一覧は Paging 3、画像は Coil」と決めていた。Phase 1 の実装で次の問題が出た。

- Coil 3（coil-compose 3.6.3）は JetBrains の KMP 版 Compose（`org.jetbrains.compose.ui` / `foundation` 1.12.0）に依存する。Compose BOM の管理外になり、androidx の Compose UI が 1.7.6 から 1.12.0 に引き上がった。AGP 8.7.3 と compileSdk 35 では解決できずビルドが失敗した。
- Paging 3 は必要範囲だけを読むため、日付見出しや右端スクロールバーの「この日付へジャンプ」を正確に作れない。見出し位置には全件の日付インデックスが必要になる。
- 依存注入に Hilt を入れるか未確定だった（計画書の未確定事項）。画面は 1 つで依存も少ない。

## 決定内容

1. サムネイルは Coil を使わず、`ContentResolver.loadThumbnail`（API 29 以上。minSdk 34 で利用可）と `LruCache` で読み込む。
2. 一覧は Paging 3 を使わず、MediaStore から id・撮影日時（DATE_TAKEN、無ければ DATE_ADDED）だけを一括取得してメモリに持つ。サムネイルは表示時に読む。
3. 依存注入は手動（ViewModel 内で Repository を組み立てる）とし、Hilt は導入しない。

## 検討した代替案

| 案 | 概要 | メリット | デメリット |
|----|------|---------|----------|
| 案A（採用） | loadThumbnail + LruCache、全件インデックス、手動 DI | ビルドが安定。依存が少ない。日付見出しとジャンプが正確 | 動画の一部形式でサムネイルが取れない可能性。ディスクキャッシュは無し |
| 案B | Coil 3 を使い、Compose BOM 側で UI バージョンを揃える | 画像処理が豊富。ディスクキャッシュあり | KMP 版 Compose の依存が入り、AGP・compileSdk との組み合わせが難しい |
| 案C | Coil 2.x を使う | androidx 依存のみで済む | 旧系統で保守性が低い。将来の移行コストがある |
| 案D | Paging 3 で必要範囲のみ読む | 大量データでもメモリが少ない | 見出しとスクロールバーの正確なジャンプが難しい |

## 理由

ビルドが通ることを最優先にした。Coil 3 は導入コストに見合わない。MediaStore のインデックス（id と日時の数値だけ）は数万件でも小さく、全件保持で十分。見出しとジャンプの正確さを優先した。Hilt は画面 1 つに対して過剰と判断した。

## 結果・影響

- **ポジティブ**: 依存が少なくビルドが安定する。日付見出しと右端スクロールバーが正確に動く。
- **ネガティブ**: ディスクキャッシュが無いため、再表示時は再読込になる。全件の日時を保持するためメモリを使う。
- **リスク**: `loadThumbnail` が一部の動画や HEIC で失敗する可能性。大量データ（数万件以上）での実機検証が必要。
