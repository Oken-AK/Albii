# ADR-0006: 動画はアプリ内で Media3 ExoPlayer により再生し、シークバー操作に映像を追従させる

**ステータス**: Accepted

**日付**: 2026-11-05

**決定者**: GitHub Copilot（ユーザー指示「プラン通りに実装を開始」により選定）

---

## コンテキスト

動画は、ビューアの「再生」ボタンから外部アプリを `ACTION_VIEW` で起動する実装だった。実機（Pixel 10a / Android 17）で次の問題が出ている。

1. **再生すると落ちる**: `SecurityException: UID … does not have permission to content://media/external/video/media/…`。書き込み権限まで付けて `startActivity` していたため、他アプリ所有の動画でシステムに拒否され、例外が握られず落ちる（詳細は [viewer-video-improvements-plan.md](../../plan/viewer-video-improvements-plan.md)）。
2. **シークバーに追従させたい**: 「Apple のように、シークバーを操作したら動画も追従する。前後どちらにも動かせる」という要望がある。外部アプリでは再生位置を制御できず、実現できない。

## 決定内容

動画は外部アプリへ渡さず、`androidx.media3:media3-exoplayer:1.8.1` でアプリ内再生する。コントロールは Compose で自作し（`media3-ui` は使わない）、映像は `TextureView` に出す。シークバー操作中は一時停止してスロットル付きで `seekTo` を発行し、指の位置の映像に追従させる。

## 検討した代替案

| 案 | 概要 | メリット | デメリット |
|----|------|---------|----------|
| 案A（採用） | Media3 ExoPlayer ＋ Compose 自作コントロール＋`TextureView` | シークを細かく制御でき、追従を自前で作れる。依存が最小（exoplayer のみ）。遷移アニメーション（拡大縮小・フェード・角丸）と相性が良い | コントロール・縦横比・エラー表示を自分で作る |
| 案B | Media3 ExoPlayer ＋ `media3-ui` の `PlayerView` | 部品が揃っている | 依存が増える（AppCompat 系を含む）。標準コントローラーでは追従の細かい制御と見た目の統一が難しい |
| 案C | プラットフォームの `MediaPlayer` | 追加依存なし | 対応形式・エラー処理・シークの制御が弱い。プロジェクトの技術方針（Media3、AGENTS.md）から外れる |
| 案D | 外部アプリ起動を残し、読み取り権限のみにする | クラッシュは直る。変更が最小 | シークバー追従が実現できない。外部アプリ依存で体験が揃わない |

## 理由

- 要望の核心は「シークバー操作に映像が追従する」ことで、再生位置を自分で制御できるアプリ内プレイヤーが必須。
- クラッシュの根本原因（書き込み権限の付与と、握られていない例外）は、外部起動を残す部分（画像の「編集」・共有）でも同時に直す。
- `media3-ui` を使わないことで依存を最小に保ち、APK への影響と AppCompat 由来のテーマ依存を避けられる。
- `TextureView` は通常のビューとして合成されるため、ページャでのスライドや、後続の開閉アニメーション（拡大縮小・角丸クリップ・アルファ）でも映像が崩れにくい。`SurfaceView` は別レイヤーになり、これらで破綻しやすい。
- バージョンは、現行の compileSdk 35 / AGP 8.7.3 のまま入れられる最新の安定版 1.8.1 を選ぶ（1.10 以降は `minCompileSdk=36`）。

## 結果・影響

- **ポジティブ**: 動画がアプリ内で再生でき、前後どちらへのスクラブにも映像が追従する。外部アプリ依存が減る。
- **ネガティブ**: APK サイズが増える（ExoPlayer 本体と各種デコーダー管理コード）。コントロール UI を自前で保守する。
- **リスク**:
  - スクラブ中の `seekTo` の頻度が高すぎると、デコーダーのフラッシュが続いて映像が更新されない。最新位置を優先するスロットルで抑える。
  - `SeekParameters.EXACT` は、キーフレーム間隔が長い動画で 1 回の応答が遅くなる。短尺では最も滑らかだが、重い場合は `CLOSEST_SYNC` へ切り替える余地を残す（実機で確認する）。
  - Media3 はネットワーク用の権限を要求しない想定だが、マージ後のマニフェストで INTERNET 権限が増えていないことを検証する。
  - ハードウェアデコーダーの数には限りがあるため、プレイヤーは表示中の動画ページだけに作り、離れたら必ず解放する。
